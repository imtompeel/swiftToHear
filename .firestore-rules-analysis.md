# Firestore rules analysis (sessions + signalling)

Untracked working notes.

## Auth model (updated)

- Hosts and joiners use Firebase Auth.
- Joiners call `ensureSignedIn()` → `signInAnonymously()` when needed.
- Participant `id` is `auth.uid`; `participantIds: string[]` is kept in sync for rules.

## Signalling ACL

- Messages include `baseSessionId` (Firestore session/groupSession doc id).
- Create requires membership via `hostId` or `participantIds`.
- List/read requires the same membership, constrained by `baseSessionId` in the query.
- Targeted `to` checks cannot be applied to list queries (rules are not filters); the client ignores messages not addressed to the current user.

## TURN / SFU

- Mesh uses `getIceServers()` (Metered or static TURN + Google STUN).
- Optional Daily SFU via `VITE_VIDEO_PROVIDER=daily` + `VITE_DAILY_TOKEN_URL`.
